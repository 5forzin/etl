# Writing project docs

Lead with the task and the command that completes it. Describe behavior present
in the code; put proposed features in the roadmap. An example must run as written
or name the values the reader has to replace.

Cut repeated introductions, generic claims of robustness, promotional adjectives
and conclusions that repeat the page. Prefer verbs to abstract nouns. Explain a
technical term where it changes a decision; do not turn every sentence into a
warning or every paragraph into a checklist. Keep tables for actual comparisons.

These choices follow the [gov.br editing guide](https://www.gov.br/pt-br/guia-de-edicao-de-servicos-do-gov.br/escrevendo-o-seu-texto)
and [NN/g's study of generative writing](https://www.nngroup.com/articles/genai-write-for-the-web/).
They improve clarity; they are not a test of whether a person or a model wrote a
sentence.
